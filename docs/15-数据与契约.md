# 15 — 数据与契约

> **状态**：设计稿（2026-10-30）。
> **前置**：[11](11-架构锚定.md) 定数据所有权与端口（AR23 / AR32 / AR33）；[12 §10.1](12-技术栈选型.md) 定 zod / Kysely / better-sqlite3 / UUIDv7。
> **本文交付**：表的归属与字段、端口的签名、契约测试骨架、迁移规则。
> **不是最终 DDL**：字段可在实现时微调；**表的归属与唯一写者不调整**（调整即架构变更）。

---

## 一、通用约定

| 项 | 约定 |
|---|---|
| Schema 真源 | **zod**（先 schema 后类型），类型一律 `z.infer`（N3；手写重复类型视为违规） |
| 主键 | `TEXT`，**UUIDv7**（时间有序，索引局部性好） |
| 时间 | `TEXT`，ISO-8601 **UTC**，带毫秒；展示时再转本地时区 |
| 布尔 | `INTEGER` 0/1 |
| 结构化字段 | `TEXT` 存 JSON，**写入前过 zod 校验**（不用 SQLite 的 JSON 函数做查询） |
| 必填审计列 | 所有业务表带 `created_at`；可变表带 `updated_at` |
| 删除 | 默认**不物理删除**；需要时用 `deleted_at` 或语义化状态（记忆用 `superseded_by`） |
| 迁移 | 每模块独立（见 §七） |

---

## 二、库的划分

| 账 | 载体 | 归属 |
|---|---|---|
| **会话账**（对话） | dsh session log | 宿主；**只经公开事件读**，不解析文件 |
| **业务账** | `ops.sqlite`（单库单文件） | 我们 |
| **配置默认层** | `config/*.yaml` | 我们（人可编辑） |
| **配置覆盖层** | `settings` 表 | 管理面（Web 渠道）唯一写 |
| **记忆正本** | `memory/*.md` + `memory_facts` | 模块 ⑥ |
| **快照** | restic 仓库 + `snapshots` 表（元数据） | 模块 ⑦ |

**为什么单库**：备份、快照、迁移都简单；跨模块禁止直写，所以不需要分库来"隔离"。

> **修正 12 §10.1 第 11 项**：单库多模块时 `PRAGMA user_version` 只够一个模块用，改为
> `schema_migrations(module, version)` 复合主键（见 §七）。

## 三、表设计（按模块）

> 每张表标注 **唯一写者**；"可重建"指删掉后能由其它正本或外部事实重建。

### 模块 ① 渠道网关

**`inbox`** — 入站消息（可重建，非正本）

```sql
CREATE TABLE inbox (
  id            TEXT PRIMARY KEY,
  channel_id    TEXT NOT NULL,
  msg_id        TEXT NOT NULL,            -- 渠道消息 ID（飞书 event_id）
  kind          TEXT NOT NULL,            -- message | card_action | control
  actor_id      TEXT,
  content_json  TEXT NOT NULL,
  status        TEXT NOT NULL CHECK (status IN
                  ('accepted','triaged','routed','done','failed','rejected')),
  error_code    TEXT,
  received_at   TEXT NOT NULL,
  processed_at  TEXT
);
CREATE UNIQUE INDEX ux_inbox_dedup ON inbox(channel_id, msg_id);   -- 落库即去重（AR28）
CREATE INDEX ix_inbox_status ON inbox(status, received_at);
```

**`actors`** — 主体（**正本**）

```sql
CREATE TABLE actors (
  id           TEXT PRIMARY KEY,
  kind         TEXT NOT NULL CHECK (kind IN ('owner','system')),
  display_name TEXT,
  created_at   TEXT NOT NULL
);
```

**`channel_bindings`** — 渠道身份 ↔ actor（**正本**）

```sql
CREATE TABLE channel_bindings (
  id                TEXT PRIMARY KEY,
  actor_id          TEXT NOT NULL,
  channel_id        TEXT NOT NULL,        -- 飞书 app_id
  external_user_id  TEXT NOT NULL,        -- 飞书 open_id
  bound_at          TEXT NOT NULL,
  revoked_at        TEXT
);
CREATE UNIQUE INDEX ux_binding_live
  ON channel_bindings(channel_id, external_user_id) WHERE revoked_at IS NULL;
```

**`session_routes`** — 渠道会话 ↔ dsh session（可重建）

```sql
CREATE TABLE session_routes (
  channel_id  TEXT NOT NULL,
  thread_id   TEXT NOT NULL,              -- 飞书 chat_id
  session_id  TEXT NOT NULL,
  project_id  TEXT,
  updated_at  TEXT NOT NULL,
  PRIMARY KEY (channel_id, thread_id)
);
```

**`channel_caps`** — 能力声明缓存（可失效重建）：`channel_id` PK、`caps_json`、`checked_at`。

### 模块 ② 策略与判级

**`policy_rules`** — 规则配置（**正本**，来自 `config/policy.yaml` 加载 + 覆盖层）

```sql
CREATE TABLE policy_rules (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  priority    INTEGER NOT NULL,           -- 小者先匹配
  match_json  TEXT NOT NULL,              -- {domain, pathGlob, commandPattern, network}
  verdict     TEXT NOT NULL CHECK (verdict IN ('R0','R1','R2','R3','ask','block')),
  enabled     INTEGER NOT NULL DEFAULT 1,
  updated_at  TEXT NOT NULL
);
```

**`decisions`** — 每次判级留痕（**只追加**）

```sql
CREATE TABLE decisions (
  id             TEXT PRIMARY KEY,
  correlation_id TEXT NOT NULL,
  stage          TEXT NOT NULL CHECK (stage IN ('S1','S2','jev','fallback')),
  input_digest   TEXT NOT NULL,           -- 原文不回存（AR16）
  verdict        TEXT NOT NULL,
  confidence     REAL,
  reason         TEXT,
  created_at     TEXT NOT NULL
);
CREATE INDEX ix_decisions_corr ON decisions(correlation_id);
```

### 模块 ③ 审批与授权

**`approvals`**（**正本**）

```sql
CREATE TABLE approvals (

  task_id         TEXT,
  correlation_id  TEXT NOT NULL,
  level           TEXT NOT NULL CHECK (level IN ('R2','R3')),
  summary         TEXT NOT NULL,          -- "要做什么"
  impact_json     TEXT NOT NULL,          -- 动哪些资源

  requested_at    TEXT NOT NULL,

  decided_at      TEXT,
  decided_by      TEXT,                   -- actor_id
  channel_id      TEXT,                   -- 渲染在哪个渠道

  nonce_consumed_at TEXT                  -- 防重放（一次性）
);
CREATE INDEX ix_approvals_pending ON approvals(status, requested_at);
```

**`grants`**（**正本**）

```sql
CREATE TABLE grants (
  id                TEXT PRIMARY KEY,

  scope_json        TEXT NOT NULL,        -- 域/路径/动作集合

);
```

### 模块 ④ 审计与证据

**`audit_log`** — 只追加 + 哈希链（**正本**）

```sql
CREATE TABLE audit_log (
  seq             INTEGER PRIMARY KEY AUTOINCREMENT,  -- 连续，链靠它
  id              TEXT NOT NULL,
  ts              TEXT NOT NULL,
  actor_id        TEXT,
  action          TEXT NOT NULL,
  target          TEXT,
  correlation_id  TEXT,
  payload_digest  TEXT NOT NULL,          -- 原文只留摘要（AR16）
  prev_hash       TEXT,                   -- 上一条 hash
  hash            TEXT NOT NULL
);
CREATE TRIGGER audit_no_update BEFORE UPDATE ON audit_log
  BEGIN SELECT RAISE(ABORT, 'audit_log is append-only'); END;
CREATE TRIGGER audit_no_delete BEFORE DELETE ON audit_log
  BEGIN SELECT RAISE(ABORT, 'audit_log is append-only'); END;
```

## 四、单一写者矩阵（架构约束在数据上的落地）

| 表 | 唯一写模块 | 谁可读 |
|---|---|---|
| `inbox` `session_routes` `channel_caps` `channel_bindings` `actors` | ① 网关 | 其余经 API |
| `policy_rules` `decisions` | ② 策略 | 审计只订阅 |
| `approvals` `grants` | ③ 审批 | 网关读只读视图（渲染用） |
| `audit_log` | ④ 审计 | 管理面只读 |
| `tasks` `task_events` `task_assertions` `receipts` `outbox` | ⑤ 任务 | 看板读只读视图 |
| `projects` `memory_facts` `memory_edges` `memory_docs` | ⑥ 记忆项目 | 策略只读视图 |
| `inspections` `changes` `snapshots` | ⑦ 运维 | 管理面只读 |
| `settings` | 管理面（Web 渠道） | 其余只读视图 |

> **读也走 API / 只读视图**（AR33）；需要跨表查询时，由 owner 提供视图，别处不得 join。

## 五、端口契约（签名）

**统一错误类型**（适配器必须翻译成它，不得抛裸错）

```ts
type PortError =
  | { kind: 'Unavailable'; retryable: false; detail: string }
  | { kind: 'Transient';   retryable: true;  retryAfterMs?: number }
  | { kind: 'RateLimited'; retryable: true;  retryAfterMs?: number }
  | { kind: 'Timeout';     retryable: true }
  | { kind: 'PermissionDenied'; retryable: false }
  | { kind: 'NotFound';    retryable: false }
  | { kind: 'Conflict';    retryable: false }
  | { kind: 'InvalidInput'; retryable: false }
  | { kind: 'BudgetExceeded'; retryable: false }
  | { kind: 'NotSupported'; retryable: false };

type Result<T> = { ok: true; value: T } | { ok: false; error: PortError };
```

**关键端口（节选；完整签名进 `contracts/`）**

```ts
interface ChannelPort {                                   // 4 项必需
  capabilities(): Promise<Result<ChannelCaps>>;
  identify(raw: RawInbound): Result<ExternalIdentity>;     // (channel_id, external_user_id)
  deliver(msg: OutboundMessage): Promise<Result<DeliveryRef>>;
  ack(ref: DeliveryRef): Promise<Result<DeliveryStatus>>;  // 可选能力，不保证
}

interface ExecPort {
  run(argv: string[], opts: { cwd: string; timeoutMs: number; signal?: AbortSignal;
                              idempotencyKey?: string }): Promise<Result<ExecResult>>;
  readFile(path: string): Promise<Result<{ content: string; sha: string }>>;
  writeFile(path: string, content: string, expectSha?: string): Promise<Result<{ sha: string }>>;
}

interface SvcOpsPort {
  list(): Promise<Result<UnitInfo[]>>;
  status(unit: string): Promise<Result<UnitStatus>>;
  start(unit: string): Promise<Result<void>>;
  stop(unit: string): Promise<Result<void>>;
  logs(unit: string, opts: { since: string; limit: number }): Promise<Result<string>>;
}

interface SchedPort {                                     // 只投原 session
  schedule(spec: { cron: string; sessionId: string; payload: unknown }): Promise<Result<{ id: string }>>;
  cancel(id: string): Promise<Result<void>>;
}
```

**约定**：`ports/` 内**不得出现协议名、命令行、产品名**（AR32），只允许能力动词 + 结构化数据。
`ExecPort.run(argv)` 收的是**参数数组**，不是 shell 字符串——避免拼接歧义。

## 六、契约测试骨架（corpus）

```
contracts/
  common/            PortError / Result / ids / time（zod schema）
  channel/{schema.ts, port.ts, cases/*.json}
  exec/ ...          （同构）
```

**每条端口至少 5 类用例**

| 类 | 用例 |
|---|---|
| 正常 | 一次成功调用，断言返回值形状 |
| **错误翻译** | 每种 `PortError` 至少一条（适配器不得抛裸错） |
| 超时 / 取消 | `signal` 触发后必须尽快返回 `Timeout`，不漏资源 |
| 幂等 | 同 `idempotencyKey` 重复调用不产生第二次副作用 |
| 探活失败 | 适配器不可用时返回 `Unavailable`，**其它端口不受影响** |

**运行**：vitest 驱动；同一套用例跑所有适配器；结果进 [12 §10.5 版本矩阵](12-技术栈选型.md)。
**门禁**：新适配器 100% 通过；老适配器回归不降级。

## 七、迁移规则

| 规则 | 说明 |
|---|---|
| 位置 | `<module>/migrations/NNN_<name>.sql`（纯 SQL） |
| 版本 | `schema_migrations(module, version)` 复合主键（**不是** `user_version`） |
| 只加不改 | 已应用的脚本不得修改；`checksum` 校验，手改即启动失败 |
| 破坏性变更 | 分三步：expand（加新列/新表）→ migrate（双写回填）→ contract（删旧） |
| 失败 | **拒绝启动**，不回退到半旧 schema（11 §四） |
| 顺序 | 启动时按 `module` 各自推进到最新，互不阻塞 |

## 八、验收

| # | 项 | 判据 |
|---|---|---|
| 1 | 建库 | 一条命令产出空库 + 全部表 + 索引 + 触发器 |
| 2 | 单写者 | 每张表在矩阵里有且只有一个写模块 |
| 3 | 端口 | 13 个端口都有 `port.ts` 与 ≥5 类用例 |
| 4 | 错误 | 9 类 `PortError` 各有可触发用例 |
| 5 | 审计 | UPDATE / DELETE 被触发器拒绝（跑一条测试验证） |
| 6 | 迁移 | 空库 → 最新版本可重复执行且幂等；checksum 篡改即失败 |
| 7 | 契约无关 | `ports/` 内无协议名 / 命令 / 产品名（lint 可验，AR32） |
