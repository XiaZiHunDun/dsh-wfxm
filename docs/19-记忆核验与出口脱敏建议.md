## 一、结论摘要

1. **最值得吸收的只有一条，而且我们缺得刚好**：文章主张把记忆核验从"事后巡检"前移到"**写入前**"（Live-Environment Curator）。
   我们的事实体检（[13 §2.5](13-核心能力方案.md)）此前的四类检查全是**事后**的——一条错误事实在巡检发现前可能已被注入几十轮对话。
   这是 V3「对话不再劣化」的直接漏点。
2. **我们缺的不是"要核验"，而是"确认"这个动作没有定义**。写入纪律第 3 条（[13 §2.3](13-核心能力方案.md)）**原来**只写了
   "`inferred` 不得直接提升为事实，需一次确认"，但**没规定确认是什么**。补上 `evidence` 与核验方式即可闭环（D19-1=A 已回写）。
3. **RMM 的强化学习重排不采纳**。需要 citation 训练回路与在线权重更新，而我们 RAG 已降为增强项、事实层明确不用 GraphRAG
   （[13 §2.6](13-核心能力方案.md)）；单人单机的数据量支撑不起策略梯度。只借"记录本轮注入了哪些事实"这一弱化点。
4. **Cursor Projects 与 StateGraph 的部分结论已在我们的设计里**：AR25 唯一前台 = CEO、子代理 = Workers；
   17 §6.1 已把"有先后依赖的步骤"列为不该并行的反例。**这两条不产生新工作项**，只作为外部佐证。
5. **Harness 外骨骼 + 代码同构断言**方向正确，但我们的不变量只活在文档里。可低成本补：把 AR32 / AR33 变成静态扫描脚本。
6. **出口脱敏是真缺口**：设计写了（[16 §二](16-部署与运行.md)、[11 §八](11-架构锚定.md)、08 H7），但**没有实现、也没有测试**。
   现在只有"日志字段白名单"这一层，工具入参与出站内容都没有统一守门人。
7. **明确不吸收 6 条（C 类）**：RMM 的 REINFORCE/Gumbel 重排、全库统一依赖图谱、并行子 Agent 舰队、
   强制行内 Citation 标签、时间旅行回放调试器（dsh 已有 `ui-trajectory`）、Lean4 式形式化证明（文章自身已否定）。

> **一句话**：吸收"**写入前核验**"与"**出口脱敏**"两条工程机制，其余作为方向佐证；
> 不要因为它把 RAG/多 Agent 讲得很热闹，就退回去改我们已经定过的取舍。

| A5 | **`redact` 纯函数 + 契约测试** | 样例集覆盖 SSH 私钥 / AWS Secret / JWT / 带密码的连接串；挂 4 处：日志、④ 审计写入前、① 渠道出站、⑥ 记忆写入前 | `plugins/redact`（`@dsh-wfxm/redact`）——✅ 已完成 2026-11-09，21 例 | 小 | 支撑 08 H7、11 §八 |

> **A1–A3 是一个闭环**：没有 `evidence` 的写时闸无从判断"吻合"；没有 A2 的复探，
> 写入时正确的事实在环境漂移后会变成新的陈旧记忆。三者缺一，都会退化成"多写了一张表"。
> **D19-1 已定 A**：A1 的契约先落，A2/A3 实现随 ⑥。
> ⑥ 第一片（`@dsh-wfxm/knowledge`，2026-11-09）已把三者接上：写时校验 + 三态闸 + 五类体检。
> **但探针目前只有 `path`**，`unit` / `port` / 运行时版本等仍是 `unverified`，
> 因此在 ⑦ 探针接线前，**只能宣称"写入前核验已落地、`path` 类可核验"**，不能宣称全部环境类事实可核验。

### A1 的两个设计细节（决定它能不能用）

1. **必须先分 `kind`**。`environment` 类（包管理器、unit 名、端口、路径、版本）可以探针核验；
   `preference` 类（"回复要简洁"、"审批阈值偏保守"）**无法探针核验**，只能靠 owner 确认。
   若不区分就直接要求"必须有证据"，等于把偏好类事实全部堵死。
2. **探不到 ≠ 矛盾**。文章的口径是"矛盾即拒绝"，但它没讨论"探针不可用"。
   我们的环境（无 docker、无 systemd、`ss` 缺失）经常探不到，此时**不能拒绝写入也不能当作吻合**，
   只能是第三种状态 `unverified`。这条与本项目"探不到的能力就不启用"（[AGENTS §5](../AGENTS.md)）一致。

### A3 的闸位与既有不变量

| 约束 | 说明 |
|---|---|
| 只读 | 探针一律 R0；不得为了让核验通过而写任何东西（AR11） |
| 不可绕 | 核验属于写入路径的一部分，不允许"先写后补"或分支跳过（AR31） |
| 唯一写者不变 | 核验结果只是写入参数，仍由 ⑥ 写（AR23） |
| 失败语义 | 探针异常 → `unverified`，**不阻塞**（fail-soft）；只有明确矛盾才拒绝 |

## 七、风险与反例

| 风险 | 说明 | 缓解 |
|---|---|---|
| 探针本身成为攻击面 | 核验要读文件、读服务状态，可能被诱导读凭据 | 探针只读且走白名单路径；输出截断 ≤200 字符；命中凭据形态即掩码（A5） |
| 核验拖慢写入 | 每条事实入库都跑探针 | 只对 `kind=environment` 且 `predicate` 在白名单内的做；其余跳过并标 `unverified` |
| 误判为矛盾 | 路径存在但语义已变（同名不同用途） | 矛盾只拒绝、**不删除**；进待复核由 owner 定夺 |
| 过度脱敏 | 把普通长字符串当 token 掩掉，影响排障 | 掩码保留前缀 4 位与长度；审计记"已掩码"而不记原值 |
| 数字幻觉 | 文章基准数字被当成预期收益 | 本文不引用其数值作为收益承诺；A6 用我们自己的基线测 |

## 八、建议实施顺序与验收

**顺序原则**：先落字段与闸位，再补复探与评测；每件独立可中止，每步真跑。

| 阶段 | 内容 | 验收（必须真跑） |
|---|---|---|
| 1 | A5 `redact` + 契约测试 | 样例集全部掩码；正常内容不受影响；**四处挂载点各有一例**（日志 / 审计 / 出站 / 记忆）— ✅ **已完成 2026-11-09**（`plugins/redact`，21 例；**① 出站**已接 `enqueueOutbox`，见 15 §三 ① 第六片；日志与 ④ 审计待接） |
| 2 | A4 不变量静态扫描 | 故意在 `ports/` 加一行 `systemctl` → 检查失败；故意跨模块 `import` 表 → 失败 — ✅ **已完成 2026-11-09**（11 例，并修掉一处真实违例） |
| 3 | A1 字段 + 写入校验 | `environment` 类缺 `evidence` 被拒；`preference` 类不要求证据；旧数据可迁移 — ✅ **已完成 2026-11-09**（`plugins/knowledge`） |
| 4 | A3 写时闸 | 吻合/矛盾/探不到三态各一例；矛盾不删旧值；探不到不阻塞 — ✅ **已完成 2026-11-09**（探针仅 `path`，其余谓词走 `unverified`） |
| 5 | A2 失效体检 + 复核候选 | 指向已删 unit 的事实 → 报 `stale`；30 天零引用 → 进复核候选；两者都不自动取代/归档 — ✅ **已完成 2026-11-09**（`mem_health`，五类全量） |
| 6 | A6 双盲报表 | 同一批任务两次运行输出三项对比，数字可复算；**结果归档、不作发布门槛**（D19-3=B）— ✅ **骨架已完成 2026-11-09**（`bench/`，13 例；真实 A/B 跑待执行器与凭据） |

> **阶段 1–6 均已落地**（阶段 3–5 随 ⑥ 第一片 2026-11-09 完成）。阶段 4 的探针覆盖仍限于 `path`；
