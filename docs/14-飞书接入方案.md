# 14 — 飞书接入方案

> **状态**：方案稿（2026-10-30）。
> **前置**：03 已定「飞书主通道」；11 定渠道契约（4 项必需 + 3 项可选）与网关职责；12 §10.2 定飞书为渠道候选。
> **边界**：本文只覆盖**渠道适配 + 网关侧接入**，不写业务。审批正本在 `Approvals` 表，飞书只负责渲染与回传点击（AR10 / §5.8）。
> **证据级别**：E2（官方文档 + SDK 文档，**未在本机跑通**）；标 ⚠️ 的为待实测项。

---

## 一、接入形态

| 项 | 选择 | 理由 |
|---|---|---|
| 连接方式 | **长连接（WebSocket）** | 服务器只需出网，**不需要公网 IP / 域名 / 端口映射**（12 §10.3 环境基线） |
| 备选 | 事件推送到自建 HTTPS（需隧道） | 仅当长连接不可用或需多实例时启用 |
| SDK | `@larksuiteoapi/node-sdk`（官方） | 自带 `WSClient` + `EventDispatcher`，省掉自建帧协议 |
| 凭据 | **宿主 credential seam**，逐操作解析 | 不在代码与配置里存明文（12 §10.1 第 15 项） |

> ⚠️ 待实测：长连接在断网/宿主机重启后的重连行为、允许的最大并发连接数。

## 二、飞书侧配置清单（前置，一次性）

| # | 配置 | 值 / 说明 |
|---|---|---|
| 1 | 创建**企业自建应用** | 拿到 `App ID` / `App Secret` |
| 2 | 开启**机器人能力** | 否则无法主动发消息 |
| 3 | 权限（scope） | `im:message`（收发）、`im:message:send_as_bot`（以机器人身份发）、接收单聊/群聊消息的读权限 |
| 4 | 事件订阅 | `im.message.receive_v1`（收消息）、**`card.action.trigger`**（卡片按钮回调） |
| 5 | 订阅方式 | **长连接**（不需要填请求地址） |
| 6 | 加密 | `Encrypt Key` 可选；长连接下建议启用，多一层保护 |
| 7 | 发布版本 | 自建应用需**创建版本并发布**，权限才生效（易漏） |

> **易错点**：权限改完不发布版本 = 不生效；`card.action.trigger` 漏订阅 = 按钮点了没反应。

## 三、事件 → `InboundMessage` 映射

| 飞书字段 | 我们的字段 | 说明 |
|---|---|---|
| `header.event_id` | `msg_id` | **幂等键**；飞书会重推，用它去重（AR28） |
| `header.event_type` | `kind` | `im.message.receive_v1` / `card.action.trigger` |
| `event.sender.sender_id.open_id` | `external_user_id` | **应用内唯一**，不随改名变化；不用 `union_id`（跨应用语义） |
| `header.app_id` | `channel_id` | 一个飞书应用 = 一个渠道实例 |
| `event.message.chat_id` | `thread_id` | 单聊/群聊都稳定 |
| `event.message.message_id` | `external_msg_id` | 回复、patch 卡片都要用 |
| `event.message.message_type` + `content`(JSON 串) | `content` | `text` / `image` / `file` / `audio` / `post` 等 |
| `event.message.create_time` | `received_at` | 服务端时间只作参考，**以落库时间为准** |

**四条约束**（来自 11 §2.2「渠道不可靠」）：

1. **不信任渠道时间**：排序用落库时间，不用 `create_time`
2. **不依赖送达状态**：回执由我们的 outbox 记录并重试
3. **不解析渠道内部状态**：只取上面这些字段，其余忽略
4. **能力运行时协商**：长度、富媒体、卡片支持不写死（见 §五）

## 四、身份与配对

```
首次接触：open_id 不在白名单 → 静默拒绝 + 审计（不回"你是谁"）
配对：owner 在 Web 渠道生成一次性绑定码 → 在飞书发 /bind <code> → 写入 actor 绑定
之后：open_id 已绑定 → actor = owner；其余 open_id 一律拒绝
```

| 规则 | 说明 |
|---|---|
| 绑定键 | `(channel_id=app_id, external_user_id=open_id)` |
| 唯一性 | 一个 actor 可绑多个渠道，**一个 open_id 只绑一个 actor** |
| 一次性码 | 5 分钟有效、用后失效、只进审计不出现在回复里 |
| 未绑定 | 静默拒绝（不暴露系统存在），计入限流 |
| 解绑 | 只在 Web 渠道可做（管理面仅 Web，AR26） |

## 五、出站渲染（按能力分级）

**能力声明（缓存，可失效重建）**

| 能力 | 飞书 |
|---|---|
| 文本 | ✅（长度上限 ⚠️ 待实测，按 4,000 字符分段保守处理） |
| 富文本 / Markdown | ✅（`post` / 卡片内 markdown） |
| 交互卡片（按钮） | ✅ |
| 文件 / 图片 | ✅（需上传素材拿 `file_key`） |
| 语音 | ✅（发送音频文件） |
| 主动推送 | ✅（可发给已绑定用户） |
| 送达回执 | ⚠️ 不作为正确性依据 |

**三种渲染形态**

| 形态 | 用在哪 | 结构 |
|---|---|---|
| **审批卡片** | R2/R3 审批 | 标题（要做什么）+ 影响（动哪些资源）+ 会话 ID + 三个按钮（批准 / 拒绝 / 看详情） |
| **进度卡片** | 长任务 | 一行状态 + 当前步骤 + 可展开的最近 5 条事件；**定时 patch，不刷屏** |
| **结果文本** | 回执 / 短答 | 结论 + 关键证据（3 行内）+ 长内容 locator（走 `spill`） |

**卡片按钮的 action value（关键设计）**

```json
{
  "approval_id": "01J...",
  "decision": "approve",
  "nonce": "一次性随机串",
  "channel_id": "cli_xxx"
}
```

- `approval_id` 让我们在**自己的表**里查到审批，不依赖卡片消息本身（AR10）
- `nonce` 防重放：只能消费一次，失败即拒
- 不把决策内容放进文本，**只信按钮回传**

## 六、审批交互闭环

```
任务提交 → 判级 R3 → Approvals 建记录 → 网关渲染卡片 → 发送（记录 external_msg_id）
   ↓ 用户点按钮
card.action.trigger（长连接收到）→ 落 inbox（event_id 去重）→ 网关解析 value
   ↓
Approval.answer(approval_id, decision, actor, nonce)  ← 旁路，不进会话
   ↓
patch 卡片（"已批准 · 12:03"）→ 删掉按钮 → 触发任务继续
```

| 场景 | 行为 |
|---|---|
| 重复点击 | `nonce` 已消费 → 返回"已处理"，不重复执行 |
| 卡片超时（默认 30 分钟） | 审批转 `expired`，同时发一条文本提醒（可再批） |
| 用户改主意 | 卡片保留"撤回"按钮，仅在任务未启动前有效 |
| 卡片被平台改版 | 降级为文本确认（"回复 1 批准 / 2 拒绝"） |
| 审批正本 | 永远在 `approvals` 表，**卡片只是视图** |

## 七、失败与重试

| 场景 | 行为 |
|---|---|
| 长连接断开 | 指数退避重连；期间入站丢失由**飞书重推**补（依赖 `event_id` 幂等） |
| 发送失败 | 重试 3 次（退避）→ 仍失败则标 `undelivered`，进 outbox 待补 |
| 限流 | 读响应头退避 ⚠️ 阈值待实测 |
| 事件重推 | `(channel_id, event_id)` 唯一键，命中即返回上次结果 |
| 卡片 patch 失败 | 不重试超过 2 次；改为再发一条新消息（避免卡片状态与事实不一致） |
| 应用权限被撤 | 启动自检失败 → 摘除渠道（11 适配器探活规则），其余功能不受影响 |

## 八、插件剖面（AR / 11 §三·接入剖面）

飞书渠道插件**只允许启用传输能力**：

| 动作 | 允许 |
|---|---|
| `send` / `receive` / `identity` / `capability` | ✅ |
| `session.create` / `approval.decide` / `task.create` / `config.write` | ❌ 禁用 |

启动自检比对"实际注册的动作集 ⊆ 剖面"，超出即**拒绝启动**（fail-closed）。
若该插件无法分项关闭自建 session / 审批 → **淘汰**（03 前置淘汰条件）。

## 九、验收清单（冒烟用）

| # | 项 | 通过判据 |
|---|---|---|
| 1 | 长连接建立 | 日志出现连接成功，**且外网未开任何入站端口** |
| 2 | 收消息 | 手机发一句，服务端 1 秒内落 `inbox` |
| 3 | 回消息 | 收到回复，且带 `external_msg_id` 记录 |
| 4 | 卡片按钮 | 点"批准"→ 审批表状态变更 → 卡片 patch 为已批准 |
| 5 | 幂等 | 同一 `event_id` 重放 → 不重复执行 |
| 6 | 未配对 | 陌生 open_id 发消息 → 静默拒绝 + 审计有记录 |
| 7 | 断线恢复 | 手动断网 30s → 恢复后仍能收发 |
| 8 | 剖面 | 插件未注册被禁用的动作集（或整包淘汰） |
