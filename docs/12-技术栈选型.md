## 一、冒烟测试取代验证阶段

原则：**能用更保守的选型消除的不确定性，就不要用实验去验证。**

| 原风险 | 保守选型 | 结果 |
|---|---|---|
| 本机 Node 22.13 不满足 `engines` | 直接装 **Node 24 LTS** | 消除 |
| `node:sqlite` 仍是实验特性 | 用 **better-sqlite3** | 消除 |
| 同一 session 能否并发 resume 未知 | **一个 workspace 同一时刻只允许一个活跃写任务** | 消除（牺牲并行，后续再放开） |
| 审批重启后能否恢复未知 | 审批状态**自己持久化**在业务库，宿主只当传输层 | 消除 |
| 长任务进度微信不可见 | 已知 dsh-im 只有 typing + 1800 字分段 → **自写进度出站** | 消除（已知项，不是未知） |
| 同文件并发 | 默认串行 + 文件锁兜底 | 消除（本来就不是分叉点） |

**只剩一件只能实测的事**：dsh + 渠道插件这条链能否跑通。它不是验证阶段，
而是落地路线 Step 2 的第一个冒烟测试：装、发一条消息、看回复。

## 二、选型原则

1. **单机优先，不加中间件。** 没有 Redis、Postgres、Kafka、K8s 的位置——每个都只增加运维面。
2. **有 seam 就不自建。** 宿主已有模型、沙箱、浏览器、搜索、MCP、审批、调度、存储、凭据的缝，只在缝上补语义。
3. **协议/格式重的用现成，治理/产品语义自建。** 邮件协议、CalDAV、SQLite、TLS 不自己写；风险判级、任务状态机、审计链必须自己写。
4. **版本锁定 + 契约测试。** 宿主明文承诺破坏兼容；第三方也要能换。
5. **每个第三方都有退出路径。** 至少一个替代方案，且不把数据锁死在它的私有格式里。
6. **适配器只做映射。** `adapters/` 内不写判级、重试策略、状态判断——这些属于内核；
   适配器一旦出现业务分支，说明边界破了（[11 AR24](11-架构锚定.md)）。
   能用现成插件就不自己写适配器；**减少胶水存量比优化胶水更重要**。

#### 适配器验收（每个端口都要过）

换适配器的判据不是"能跑通一次"，而是下面六条全过：

| # | 验收 | 判据 |
|---|---|---|
| 1 | **契约实现无关**（AR32） | `ports/` 内零协议名 / 命令 / 产品名 |
| 2 | **错误翻译** | 每个端口错误都有对应内核分支；**区分 Transient 与 Permanent** |
| 3 | **能力运行时协商** | 能力从适配器读，不在内核写死（长度、富媒体、交互控件、限速） |
| 4 | **探活与摘除** | 停掉适配器，链路给**明确的不可用**，不静默降级；多适配器时只摘自己 |
| 5 | **选择规则在内核** | 一个端口挂多个适配器时，由内核选，适配器不"抢单" |
| 6 | **契约测试同组用例** | 换实现跑同一套 conformance，不新写一套 |

> 完成度按**通过上述六条的端口数**计，不按代码行数计。

> **MCP 不在这张表里——它不是端口，是"工具来源"。** 客户端把外部工具注入工具列表，
> 但每个工具都要过判级、审计与白名单（K2）；单个 server 挂掉只摘除它自己的工具（L15）。
> 优先用 MCP 吸收长尾集成（日历、家居、监控、云 API），**核心能力不走 MCP**（10 D17）。
> **MCP 的工具名不得写进 prompt / skill**，须包一层自有工具名，否则换 server 即任务失效（AR4）。

## 四、四层技术栈

### Layer 0 — 宿主

| 项 | 选型 | 说明 |
|---|---|---|
| Agent 宿主 | `@deepseek-ai/dsh`，**运行锁 `0.2.1-rc.2`** | 依赖，不是源码；不 fork |
| Profile 基座 | `@deepseek-ai/dsh-base` | 共享核心：模型、工具、持久会话、安全默认 |
| 我们的打包 | 自定义 profile + **一个自有 bundle** | 多个插件放进一个 bundle，减少 peer 不匹配面 |
| 不用 | `headless`（一次性任务，无长驻）、`web-app`（自带 UI，v1 不需要） | — |

> 源码快照是 `0.2.1-alpha.3`，但插件生态验证基线是 `0.2.1-rc.2`。**运行版本跟 rc.2，源码只作参照。**

### Layer 1 — 运行时底座

| 项 | 选型 | 理由 |
|---|---|---|
| Node | **24 LTS** | 宿主 `engines` 允许 `>=24`；避开 22 的实验特性与版本债 |
| 包管理 | **pnpm 11.28.5** | 宿主要求 |
| 语言 | TypeScript（ESM） | 与宿主一致 |
| 构建 | **tsdown** | 宿主自己用它 |
| 测试 | **vitest** | 宿主自己用它 |
| 插件内核 | **Cordis**（宿主 vendor 版） | 不另引入 DI 框架 |

### Layer 1.5 — 契约与生成（N3 / N5）

| 用途 | 选型 | 约束 |
|---|---|---|
| Schema 真源 | **zod** | 先 schema 后类型；**手写重复类型视为违规**（N3） |
| 生成 | **zod → JSON Schema → TS**；HTTP 面用 `openapi-typescript` | 生成物禁止手改（AR21） |
| 文档 | 结构化能力清单 → Markdown | 数字 / 版本取自生成物或配置（AR22） |

> 这一层很小，但它是"可替换"能不能成立的前提：端口契约没有 schema，就无法生成契约测试。

### Layer 2 — 现成组件

| 用途 | 选型 | 理由 | 替代 |

| 浏览器 | **Playwright** | 宿主已有 provider 槽 | Chrome DevTools MCP |
| PDF 抽取 | **poppler `pdftotext`** | 稳定、无运行时依赖 | pdfjs |
| 语音转写 | **whisper.cpp**（P1，可选） | 本地、无 Python 服务 | 云 ASR |
| 备份 | **restic + `VACUUM INTO`** | 快照 + 加密 + 异地 | Litestream |

### Layer 2.5 — 插件生态复核（2026-10-28）

插件生态比 10 月中旬的假设大得多。但**各插件目录自报数字互相矛盾**（280+ / 1,819"真插件" / 6,000+ / 11,000+），
**目录数字不可作供给依据**；实测 GitHub topic 为 `deepseek-harness-plugins` **293**、`deepseek-harness-plugin` **922**（2026-10-29）。
结论：**能装插件的不要自建；自建只保留治理与产品语义。**

| 用途 | 候选（实测） | 结论 |
|---|---|---|
| 渠道 | `@xmanrui/dsh-im@5.7.0`（MIT）：微信/飞书/企微/钉钉/QQ/Slack/Telegram/Discord/WhatsApp/Matrix；流式、文件/图片、语音<br>`dsh-im-gateway@0.3.3`（MIT，106 tests，25+ 平台）：统一会话 + **远程审批 + 交互提问** | **二选一**，冒烟对比后定；两者自带"统一会话/远程审批"**不得绕过 Gateway（AR12）与审批解耦（11 §5.8）** |
| 邮件 | `dsh-email@0.20.3`（MIT）：IMAP/SMTP、8 家预设、多账号、草稿、发送前审批、可信/黑名单 | **采用**；J1–J3 不自建 |
| 日历 | CalDAV 插件（iCalendar/RRULE/时区） | **候选**，验收后采用 |
| 记忆 | 441 个候选：Markdown 型（`dsh-evolving-memory`）、SQLite+FTS5 型 | **只作索引/检索**；正本存我们自己的库与 Markdown |

| 审批 | `dsh-approval-flow-poc`（默认拒绝） | **只作参考**；仍用宿主审批 seam |

| 审计 | `dsh-change-ledger` 是会话级变更记录 | **自建**（跨会话 + 哈希链） |
| 系统服务 | 实测：systemd 检索仅 **7 个且全 0★**（只是"重启按钮/自启动"）；`backup` 检索 **0**；`opskat`（701★）为 GPL-3.0 独立面板 | **确认自建** svcops（Step 4 立项成立） |

| 备份 | 插件多是会话备份，不是系统备份 | **restic** |

**插件准入评分（M10 落地）**：star/贡献者、最近提交、License、peer 范围、是否写自有数据格式、
是否有测试、卸载是否干净、是否有出站网络行为、**能否按剖面分项启用**（[11 §三·接入剖面](11-架构锚定.md)）、
**拔插件可重建**（删掉插件与其索引后，正文与检索结果可由自有正本重建，AR5）。
**不满足 5 项不进核心 bundle；其中 License 与"能否分项启用"是硬门槛，不参与打分。**

### Layer 3 — 直接用宿主的插件能力

| 能力 | 怎么用 |
|---|---|
| Agent loop / 工具调用 | 直接用 |
| 会话与事件日志 | 对话真相源（AR2） |

| 持久存储 | 简单 KV；**不支持跨表事务/CAS** → 业务库不自建在它上面 |
| 凭据 | 引用式、逐操作解析 |
| MCP | 接长尾工具 |
| 浏览器 | 缺持久 profile |
| 搜索 | 直接用 |
| 文档/附件 | 图片/文件输入 |
| 子代理 | 注意：**共享父治理**，用前需单独验权限边界 |
| 技能 | 把常用流程做成 skill |
| **管理面 UI** | `ui-approval` / `ui-jobs` / `ui-plan` / `ui-permission-presets` / `ui-agent-preset` / `ui-plugin-manager` / `ui-settings-session-log` / `ui-deliverables` / `ui-trajectory` / `ui-secret-mask` 直接用；**只需自建跨会话任务视图、审计检索、Grant 管理** |
| **计划审批** | `plan/plan-mode`：先出计划再批准，状态随 resume/fork 存活 → 直接支撑"确认计划而非单动作" |
| **大输出外溢** | `spill` + `spill-local` + `spill-policy`：超长文本落盘返回 locator，替代 1800 字切段 |
| **契约生成** | `typert`（registry + generator）：构建期从类型生成 schema 与声明，正好对应 N3/N5 |
| **事件入站** | `experimental/webhook`：内置动作是**新建 root Session**，违反 AR25 → 必须注册自定义规则走 Gateway→dispatcher |
| **远端执行** | `ssh` / `fs-ssh` / `subprocess-ssh` / `sandbox-ssh`：B 域可跨主机 |
| **并行隔离** | `experimental/worktree`：每任务一个 worktree，对应 E4 |
| **语音转写** | `experimental/speech-to-text`(+`sensevoice`)：A8 语音输入（实验性，需验收） |
| **可观测导出** | `telemetry/otel`：省掉自建 metrics 管线（P2） |
| **测试件** | `test-support/*`（`llm-replay` / `llm-mock-server` / `session-snapshot` / `agent-loop-testkit` / `tool-testkit`）：L1 契约测试与回归 |
| **限域策略** | `sandbox-policy` / `fs-observation-policy`：AR11 双闸的一部分可复用 |
| **工作流 / PTC** | `workflow` / `tool-workflow` / `workflow-ptc` / `ptc-runtime*`：只作执行域与步骤实现，**不接管编排**（AR29） |
| **目标对象** | `goal` / `tool-goal` / `command-goal`：D21 已定不引入 Goals，仅借用计划展示 |

### Layer 4 — 必须自建的插件（内核）

| 模块 | 对应 11 | 为什么必须自己写 |
|---|---|---|
| **PolicyGate**（风险判级 + 编排策略） | 准入与判级；编排策略 | 判级规则与编排规则是产品语义；编排用扩展点组合，不替换 loop（AR29） |
| **TaskStore / TaskWorker**（D9–D11） | 任务编排 | 宿主无跨会话持久队列；`jobs` 是 session 作用域 |
| **AuditStore**（只追加 + 哈希链） | 审计 | 宿主审计在会话日志里，不可跨会话查询 |
| **ProjectRegistry** | 项目注册 | 产品概念，宿主无"项目" |
| **Memory 正本 + 治理层** | 记忆治理 | 正本必须在我们手里（AR5） |
| **svcops**（systemd/docker） | SvcOpsPort | 宿主与 WFXM 都没有 |
| **邮件/日历策略层** | MailPort / CalendarPort | 发送审批、可信收件人、配额是产品语义 |
| **入站准入与配对** | 准入 | 渠道扫码新建默认放开，必须外层 fail-closed |
| **Patrol / Alert 策略** | 巡检/告警 | 巡检清单与打扰分级是产品语义 |
| **Backup / Restore 编排** | 变更与回滚 | 需要知道"备份什么、怎么恢复" |
| **Schema 迁移 + 启动自检**（M3/M4） | 部署形态 | 宿主无迁移与看门狗；需 `user_version` + 自检清单 |
| **供应链清单**（M10） | 假设 S7 | 版本锁定现在就要；SBOM / 许可证扫描放 P2 |
| **Provider 契约测试**（L1） | 全部端口 | 没有它，"可替换"是假的 |
| **插件准入与版本矩阵** | — | 11,000+ 插件，必须白名单 + pin + 契约测试 |

**不自建**：agent loop、会话、模型适配、沙箱、MCP 客户端、浏览器 provider、搜索、调度原语、存储后端、凭据、审批原语。

## 六、可优化架构的外部开源件

这些**不进核心 bundle**，只作为信号源或备选，用来减少自建面积。

| 用途 | 选型 | 怎么用 | 取舍 |
|---|---|---|---|
| 巡检信号 | **MVP 自建最小采集**（`systemctl is-active` / `df` / `ss` / `journalctl`）；服务多了再上 **Gatus / Netdata** | agent 读信号，只做"解读 + 决策 + 通知" | MVP 不装常驻监控；Gatus 属条件触发（AR：管家只发现+报告） |
| 语义记忆 | **sqlite-vec** | 在业务库内做向量检索，配合 FTS5 | 避免引入 Qdrant/Chroma |
| 公网入口 | **Cloudflare Tunnel** 或 **Tailscale Funnel** | 渠道 webhook 不直接开端口；**自建中继**则自有服务器 + Caddy | 依赖第三方隧道；但攻击面最小 |
| 告警兜底 | **ntfy** | 渠道不可用时的备用通道 | 多一个推送端，只用于 P0 |
| 远程访问 | **Tailscale** | 管理面只走私有网 | 不把 SSH/管理口暴露公网 |
| 并行编辑 | **git worktree** | 每个开发任务一个 worktree，成功再合并 | 比文件锁更干净；需要合并策略 |
| 浏览器隔离 | **browserless**（可选） | 多任务并发浏览器时做隔离 | 单任务不需要 |
| 持久工作流 | **Restate**（P2 备选） | 只有出现多步、跨天、强重试流程才引入 | 不替代 v1 的 SQLite 租约 |
| 防篡改审计 | **immudb**（P2 备选） | 只有合规/取证要求才引入 | 多一个服务；SQLite 哈希链够用 |

> 原则：**信号可以外包，判断不能外包。**

## 七、明确不引入

| 不引入 | 理由 |
|---|---|
| Redis / BullMQ / Temporal | 单机 SQLite 租约足够；多一个进程就多一个故障点 |
| Postgres / Prisma / ORM | 数据量小；SQL 直写更可控 |
| Kafka / 消息队列 | 没有多消费者需求 |
| Kubernetes / Docker-in-Docker | 应用本身跑在宿主 systemd 上 |
| LangChain / LlamaIndex | 与宿主 agent loop 重复且更重 |
| 向量数据库（Qdrant/Chroma） | 单用户先用 SQLite FTS5；不够再上 |
| Grafana / Prometheus 全家桶 | v1 用 journald + 审计表；需要再加 OTel |
| 重复写渠道/邮件/日历插件 | `dsh-im` 已覆盖 10+ 渠道；`dsh-email` 已覆盖 IMAP/SMTP |
| Electron / Tauri UI | 桌面与移动复用 IM 客户端，管理面用浏览器；v1 不做原生客户端 |
| PM2 | systemd 已经做了同样的事 |
| 通用文档站 / 自研 codegen 框架 | Markdown + 现成 schema 工具就够，自研只会多一层要维护的生成器 |

## 八、适用性、置信度与可逆性

### 证据分级

| 级别 | 含义 |
|---|---|
| **E3** | 我们跑过、有输出（本轮只有少量） |
| **E2** | 一手材料：官方 README / `package.json` / 源码，但**未在本机运行** |
| **E1** | 插件目录、搜索摘要、二手转述 |
| **E0** | 仅凭架构常识推断 |

> **本文绝大多数选型是 E1–E2，不是 E3。** "信心"指**"第一次装到我们环境里就能按预期工作"的概率**，
> 不是"这个软件好不好"。

### 适用性：先问"要不要"，再问"靠不靠得住"

| 适用性 | 选型 | 判断依据 |
|---|---|---|
| **现在必需** | Node 24、pnpm 11、TS/tsdown/vitest、better-sqlite3、systemd、宿主 base + 自有 bundle | 不装就没有可运行形态 |
| **上线前必需** | restic + 还原演练、审计落库、快照回滚（M1/M2）、Caddy（若渠道需公网回调） | M 域是上线门槛 |
| **条件触发** | CF Tunnel / Tailscale（需外部访问）、git worktree（同项目并行改）、Gatus/Netdata（服务多到看不过来；**MVP 用自建最小采集，不装**）、sqlite-vec（FTS5 不够）、browserless（并发浏览器）、ntfy（P0 兜底）、Restate（跨天强重试）、immudb（合规取证） | **没触发就不装** |
| **必须先验收才采用** | dsh-im、dsh-email、CalDAV、cost-ledger、voice、memory 插件 | 证据 E1–E2 且未在本机运行 |
| **已判定不需要** | 见 §七 | 单机单用户，引入只增故障点 |

> **一句话判据**：不装也能跑 v1 的，就不进 v1 部署——但必须留在退出路径表里。

### 逐项评级

| 选型 | 证据 | 信心 | 可逆性 | 替换路径 / 成本 | 前置动作 |
|---|---|---|---|---|---|
| Node 24 LTS | E2（`engines`） | **高** | 高 | nvm 切回 22，分钟级 | 锁 minor |
| better-sqlite3 | E2/E0（成熟度） | **高** | 高 | 换 `node:sqlite`/libsql，SQL 不变；小时级 | 数据用标准 SQL |
| Playwright | E2（宿主 provider） | **高** | 高 | 换 CDP/Stagehand；profile 是 Chromium 标准格式 | profile 独立目录 |
| git worktree | E3（git 原生） | **高** | 高 | 换文件锁/串行 | — |
| restic | E2 | **中高** | 中高 | 需先用 restic 还原再换工具；小时级 | 每月做一次还原演练 |
| systemd | E3 | **高** | 中 | 平台标准；换 s6/supervisord 需改 unit | — |
| Caddy / CF Tunnel | E2 | **中高** | 高 | 换 Nginx/其他隧道；配置级 | — |
| **dsh-im 5.7.0** | E2（README/npm，**未运行**） | **中** | **中高** | 换 dsh-lark/自写适配；天级；会话仍在宿主 | 包 `ChannelPort`；配对表自己存 |
| **dsh-email 0.20.3** | E2（很新、star 少） | **中低** | **高** | 换 imapflow/nodemailer；邮件在 IMAP 服务器上；天级 | 包 `MailPort`；插件名不进 prompt |
| CalDAV 插件 | E1 | **低** | 高 | 协议标准，换客户端即可；天级 | 先验收再用 |
| dsh-cost-ledger | E1 | **低** | 高 | 自建几十行；小时级 | 当作可丢组件 |
| voice-context bundle | E1 | **低** | 高 | 换 whisper.cpp；小时级 | 语音不进 MVP |
| **memory 插件** | E1 | **低** | **低**（数据锁定） | 若正本在插件里，迁移要重写记忆 | **正本放我们库里**；插件只做检索 |
| **宿主运行版本 `0.2.1-rc.2`** | E2（插件 README 声称） | **中** | **中**（宿主级） | 升降级涉及 session 格式迁移；天到周 | pin 精确版本 + 升级前快照 |
| Gatus / Netdata | E2 | **中高** | 高 | 只读 API，随时撤；小时级 | 只读账号 |
| sqlite-vec | E1/E2 | **中** | 中 | 索引可从正文重建；小时级 | 原文另存 |
| 自建内核（PolicyGate / Task / Audit） | E0（自己的代码） | **高（可控）** | **中**（schema/ID 锁定） | 代码可换，历史数据难改 | **先冻结 ID 与 schema**（11 §十一） |

### 可拆卸的三个层次

| 层 | 含义 | 适用 |
|---|---|---|
| **L1 配置级** | 换个 provider 名字即可 | 模型、搜索、Caddy、Gatus |
| **L2 适配器级** | 写一个 Port 实现，业务代码不动 | 渠道、邮件、浏览器、日历、运维 |
| **L3 数据级** | 要迁移数据/重建索引 | 记忆、审计、任务历史 |

### 三条硬规则

1. **插件名不得出现在 prompt / skill 里。** 全部包在端口后；prompt 只认识我们的工具名（AR4）。
2. **任何插件都不得持有唯一数据副本**（AR5）。
3. **采用即写退出方案。** 每个第三方必须有"换掉它要多久、数据怎么带走"；写不出就不采用。

### 结论

- **高信心、可逆**：Node 24、better-sqlite3、Playwright、git worktree、systemd。
- **中信心、可逆（L2）**：dsh-im、dsh-email、Caddy、Gatus/Netdata。
- **低信心、可逆**：CalDAV、cost-ledger、voice——**都可以先不上**。
- **低信心、不可逆**：memory 插件——**所以正本必须自己拿**。
- **宿主级风险**：运行版本——插件生态与源码快照不同版本，必须 pin + 快照 + 矩阵。

## 十、选型定稿

**三段式：骨架定死、插件定门槛、输入待 owner。** 只有 10.1 的 9 项属于"改了要动工程结构"；
10.2 的 8 项**只定采用条件，不预先钉版本**——版本由 10.4 的冒烟组合锁定。

### 10.1 已定：骨架（9 项）

| # | 项 | 结论 | 锁定方式 | 不成立时的替代 |
|---|---|---|---|---|
| 1 | 运行时 | **Node 24 LTS + pnpm 11.28.5** | `.nvmrc` + `packageManager` + CI | 降 22 LTS（宿主允许 ≥22.19，但会踩实验特性） |
| 2 | 语言与构建 | TypeScript ESM + **tsdown** + **vitest** | 与宿主同栈 | 换 tsc/rollup；测试换 jest（天级） |
| 3 | 契约真源 | **zod**（schema 先行）+ `typert` 生成 | 生成物禁手改 + lint（AR32 / N3） | 换 valibot：**全部契约重写** |
| 4 | 业务存储 | **better-sqlite3**（WAL） | 标准 SQL + `user_version` 迁移 | `node:sqlite` / libsql：SQL 不变，数据可迁（L2） |
| 5 | 日志 | **pino → journald** | 结构化 + 字段白名单 | 接 `telemetry/otel` |
| 6 | 进程与备份 | **systemd** + **restic** + `VACUUM INTO` | unit 文件 + 备份脚本 + 每月还原演练 | s6/supervisord；Litestream |
| 7 | 浏览器 | **Playwright**（经宿主 provider） | 端口契约 + 独立 profile 目录 | CDP / Stagehand（L2） |
| 8 | 命令行工具 | **git + gh + ripgrep + poppler** | 部署清单 | 各自有等价物 |
| 9 | 打包 | **base profile + 一个自有 bundle** | lockfile + 启动自检 | 多 bundle：peer 匹配面翻倍 |

> 这 9 项定了，**目录结构、构建、测试、存储格式、部署方式**就不再反复。

### 10.2 待验收：插件（8 项）——只定条件，不定版本

| 项 | 定稿形态 | 前置淘汰（不满足即出局） | 验收判据 |
|---|---|---|---|
| **渠道** | `dsh-im` vs `dsh-im-gateway` **二选一** | 不能关闭其自建 session / 审批落库（接入剖面） | 冒烟：收到→回复；审批经我们网关；跨 surface 续跑 |
| **邮件** | `dsh-email` 包在 `MailPort` 后 | 许可证不可进核心、无可信收件人机制 | 覆盖目标邮箱商；发送前审批生效 |
| **日历** | CalDAV 客户端包在 `CalendarPort` 后 | 无 RRULE / 时区支持 | 重复事件与跨时区正确 |
| **记忆** | 只做索引与检索 | **持有正本** | **拔插件可重建**（AR5） |
| **成本** | 只做展示 | 自带账本被当正本 | 数字与 token 计数一致 |
| **语音** | P1，本地优先 | 需常驻 Python 服务 | 中文识别可用 |
| **MCP 管理** | 管理面采用 | 可绕过网关直写配置 | 改配置产出审计事件 |
| **子代理团队** | **仅评估** | 权限放大 | AR30 用例通过 |

> 版本号在冒烟通过后写入 10.4。**此处预先钉版本 = 钉一个没验证过、失败时还无声的组合。**

### 10.4 版本矩阵（随冒烟增长，唯一的版本真源）

| 组合 | dsh | Node | pnpm | channel | mail | 状态 |
|---|---|---|---|---|---|---|
| **M0 起步** | `0.2.1-rc.2` | 24 LTS | 11.28.5 | — | — | 待 Step 1 冒烟 |
| **M1** | 同上 | 同上 | 同上 | 冒烟胜出者 + 精确版本 | — | 冒烟后填 |

三条规则：

1. 每采用一个插件 = **新增一行**，不覆盖旧行；
2. 只有通过 V1–V10 的组合才可写入部署 lockfile；
3. 升级 dsh 时**整行重测**，不逐格替换（11 底座契约 4）。

### 10.5 一句话结论

- **宿主**：`base` + 一个自有 bundle，运行锁 **`0.2.1-rc.2`**。
- **底座**：Node 24 LTS、pnpm 11.28.5、TS、tsdown、vitest、Cordis、zod、better-sqlite3、pino、systemd、restic。
- **数据**：业务账在 better-sqlite3；**对话账留在会话日志**（只经公开事件读）。
- **自建件**：PolicyGate、TaskStore/Worker、Audit、ProjectRegistry、Memory 治理、svcops、入站准入、巡检策略、备份编排、插件准入与契约测试。
- **不引入**：Redis、Postgres、K8s、LangChain、向量库、监控全家桶、原生客户端。
