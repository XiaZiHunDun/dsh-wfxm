# 16 — 部署与运行

> **状态**：设计稿（2026-10-30）。
> **前置**：11 §八 部署形态；12 §10.1 骨架 15 项；15 数据与契约。
> **环境基线**：普通 Linux、可出网、**无入站暴露需求**（12 §10.3）。
> **原则**：单机、systemd、无中间件；**服务进程不以 root 运行**。

---

## 一、目录布局

```
/opt/dsh-wfxm/                 # 代码与构建产物，root:root，服务只读
  releases/<version>/          # 每次发布一个目录（蓝绿）
    dist/  node_modules/  migrations/  package.json
  current -> releases/<v>      # 软链，切换即发布/回滚
  config/
    default.yaml               # 默认层（入仓，随版本发布）
    policy.yaml                # 判级规则（可被管理面覆盖）
    patrol.yaml                # 巡检清单（最小安全集）

/var/lib/dsh-wfxm/             # 数据（正本），dshwfxm:dshwfxm，0700
  ops.sqlite  ops.sqlite-wal
  memory/                      # Markdown 正本（知识层）
  sessions/                    # 宿主 session log（只经事件读）
  spill/                       # 大文本外溢（可清理）
  outbox-files/                # 待投递附件
  browser-profiles/            # Playwright 持久 profile（按项目分目录）
  readiness                    # 就绪标记文件（本地）

/etc/dsh-wfxm/                 # 配置与凭据，root:dshwfxm，0750
  env                          # 非敏感环境变量，0640
  credentials/                 # 0600；内容为引用名，实际由宿主 seam 解析
  polkit-rules/                # 见 §三

/var/backups/dsh-wfxm/         # restic 本地仓库与暂存
/var/log/journal/              # 日志走 journald，不另建目录
```

| 规则 | 理由 |
|---|---|
| **代码只读、数据可写** | 发布不可被运行进程改写，供应链更干净 |
| 专用系统用户 `dshwfxm` | 无 login shell；不属于 sudo/docker 组 |
| 数据目录 0700 | 会话正文、邮件、凭据引用都在里面 |
| profile 按项目分目录 | 对应 AR / 11 §5.8 浏览器 profile 资源化 |

## 二、凭据注入

| 层 | 做法 |
|---|---|
| 非敏感配置 | `/etc/dsh-wfxm/env`（0640），启动时 zod 校验 |
| **敏感凭据** | **不进 env、不进 yaml**；只放**引用名**（如 `cred.feishu.app_secret`），值由宿主 credential seam 逐操作解析 |
| 开发期 | `.env`（不入仓、gitignore） |
| 日志 | pino `redact` 白名单 + 字段白名单，**凭据与不可信原文不进日志**（11 §八） |

## 三、systemd unit

```ini
[Unit]
Description=dsh-wfxm agent
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=dshwfxm
Group=dshwfxm
WorkingDirectory=/opt/dsh-wfxm/current
EnvironmentFile=/etc/dsh-wfxm/env
ExecStart=/usr/bin/node dist/cli.js serve
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure
RestartSec=5
TimeoutStopSec=30
KillSignal=SIGTERM
NoNewPrivileges=yes
PrivateTmp=yes
ProtectSystem=strict
ProtectHome=yes
ReadWritePaths=/var/lib/dsh-wfxm /var/backups/dsh-wfxm
RestrictSUIDSGID=yes
CapabilityBoundingSet=
```

**关键取舍：怎么在不给 root 的前提下管服务（`svcops`）**

| 方案 | 结论 |
|---|---|
| 服务跑 root | ❌ 一个 agent 进程 root = 全盘皆输 |
| 加入 `docker` 组 | ❌ **等价 root**（可挂载宿主根、起特权容器） |
| **polkit 细粒度授权** | ✅ 允许 `dshwfxm` 对**匹配前缀的 unit** 做 start/stop：`dsh-wfxm-managed-*.service` |
| docker socket proxy（只读/白名单） | ⚠️ 条件方案：仅当确实需要 docker 时启用 |
| 自己用 `systemd-run --user` | ⚠️ 用户态 unit，能力弱，看情况 |

```javascript
// /etc/dsh-wfxm/polkit-rules/50-dshwfxm.rules（示意）
polkit.addRule(function(action, subject) {
  if (action.id.startsWith("org.freedesktop.systemd1.manage-units") &&
      subject.user == "dshwfxm" &&
      action.lookup("unit") &&
      action.lookup("unit").startsWith("dsh-wfxm-managed-")) {
    return polkit.Result.YES;
  }
});
```

> **结论**：`svcops` 默认**只能管白名单前缀的 unit**；不在名单内的服务一律 `PermissionDenied`。
> docker 适配器**默认关闭**（12 §10.3 运行时探测 + 本节安全取舍），需要时用 socket proxy 并单独评审。

## 四、启动顺序与自检（八步，任一步失败即拒绝启动）

| # | 步骤 | 失败语义 |
|---|---|---|
| 1 | 读配置（`default.yaml` + `env`），zod 校验 | 配置错误即退出（不猜默认值） |
| 2 | 打开 `ops.sqlite`，推进各模块迁移 | 迁移失败即退出，**不回退半旧 schema**（15 §七） |
| 3 | 注册 7 个模块 | **缺任一模块即退出**（宿主 peer 不匹配会静默跳过整个 bundle） |
| 4 | 插件剖面比对 | 实际注册动作集 ⊄ 允许集 → 拒绝启动（AR / 11 §三） |
| 5 | 端口探活（每端口一次轻量调用） | 关键端口不可用 → 退出；非关键 → 降级并告警 |
| 6 | 恢复：回收过期租约、重投 `outbox`、恢复 `pending` 审批 | 失败 → 退出（宁可不开，不可半开） |
| 7 | 建立渠道长连接（飞书） | 失败 → 退出（渠道是主入口） |
| 8 | 写 `readiness` 文件 | 就绪 |

> **为什么第 6 步不能省**：崩溃后最危险的状态是"任务在跑但没人知道它跑到哪了"。

## 五、停止与崩溃恢复

| 场景 | 行为 |
|---|---|
| `SIGTERM` | 停接新任务 → 释放/冻结租约 → flush `outbox` → 断长连接 → exit |
| `waiting_approval` / `waiting_input` | **冻结租约**（不占并发槽），重启后仍是等待态 |
| 进程崩溃 | 租约到期（2× 心跳）后由恢复流程回收 → `failed` 或重排队 |
| 重复启动 | 单实例锁（文件锁 + PID），第二个进程直接退出 |

## 六、发布、升级与回滚

```
构建 → releases/<v> → 自检（空库迁移 + 契约测试）→ 切 current 软链
     → systemctl restart → 八步自检通过 → 保留上一版（N-1）
失败 → 软链切回 N-1 → restart → 报告
```

| 项 | 规则 |
|---|---|
| **我们自己的升级** | 蓝绿目录 + 软链；**N-1 永远可用** |
| **宿主（dsh）升级** | 整行重测（12 §10.5 版本矩阵），过 V1–V11 + 契约测试才进版本 |
| **DB 迁移前** | 必先 `VACUUM INTO` 备份；迁移失败用备份恢复并回滚 |
| **回滚判据** | 任一步自检失败或冒烟失败 → 回滚，不"带病上线" |
| 灰度 | 无用例：单机单用户，不做灰度 |

## 七、备份与恢复

| 项 | 做法 |
|---|---|
| 工具 | restic（加密）+ `VACUUM INTO`（SQLite 一致性快照） |
| 频率 | 每日增量；**变更前（R3 动作前）额外快照**（13 §三） |
| 保留 | 7 日 / 4 周 / 12 月 |
| **快照点一致** | `ops.sqlite` 快照 + `memory/` + `config/` **打同一 tag**（11 §四·快照点） |
| 异地 | Backblaze B2（12 §10.4 默认） |
| 审计 | **不归档、不裁剪**；随快照一起备 |
| 演练 | **每月一次真实还原**到临时目录并跑自检（纪律：没跑的测试不算绿） |

## 八、容量与并发（默认值可配）

| 项 | 默认 | 理由 |
|---|---|---|
| 活跃写任务并发 | **1** | 同 workspace 串行（12 §一 保守选型） |
| 并行对话 session | 3 | 单人够用，避免上下文互相干扰 |
| 队列上限 | 1000 `pending` | 超出拒新入站并告警（11 §三 失败语义） |
| 单任务时长 | 软上限 30 分钟 → `paused` + 告警 | 防"跑一夜没人知道" |
| `audit_log` 增长 | ~200 B/事件，10k/日 ≈ 2 MB/日 ≈ 700 MB/年 | 预算内，不裁剪 |
| journald | `SystemMaxUse=2G` | 防日志吃满磁盘 |
| 磁盘水位 | <10% 告警（巡检项） | 与 #6 最小安全集一致 |

## 十、运行手册（常见故障处置）

| 现象 | 排查 | 处置 |
|---|---|---|
| 飞书无响应 | 长连接日志、应用权限版本是否发布 | 重连；权限未发布 → 重新发布版本 |
| 任务堆积不前进 | 租约是否过期、是否有 `waiting_approval` 卡住 | 释放租约；过期审批转 `expired` 并重发提醒 |
| 启动即退出 | 八步自检哪一步失败 | 按失败步骤修；迁移失败先恢复备份 |
| 磁盘满 | `df`、`spill/`、journald | 清 `spill`；按保留策略归档；扩容 |
| **审计链断**（hash 不连续） | `audit_log` 相邻 `prev_hash` | **立即告警并停写业务**，人工介入（不自动修复） |
| 端口探活失败 | 该适配器日志 | 摘除该适配器（11 适配器探活规则），其余继续 |

## 十一、验收

| # | 项 | 判据 |
|---|---|---|
| 1 | 非 root 运行 | `ps -o user=` 显示 `dshwfxm`；unit 有 `ProtectSystem=strict` |
| 2 | 零入站 | 外部 `nmap` 扫不到开放端口；长连接正常 |
| 3 | 八步自检 | 人为破坏任一步（如删一个模块）→ **拒绝启动** |
| 4 | 迁移失败 | 注入坏迁移 → 退出且数据未变 |
| 5 | 优雅停止 | `SIGTERM` 后租约释放、`outbox` 已 flush、`waiting_*` 保留 |
| 6 | 崩溃恢复 | `kill -9` 后重启 → 任务被回收，无重复执行 |
| 7 | 蓝绿回滚 | 切到坏版本 → 自检失败 → 自动/手动切回 N-1 |
| 8 | 备份还原 | 从快照恢复到空目录 → 自检通过、抽查数据一致 |
