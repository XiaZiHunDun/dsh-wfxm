评分口径：价值看「对持续对话与任务完成的影响」，成本 S（≈1 片内）/ M（2–3 片）/ L（跨模块改造）。

|---|---|---|---|---|---|

| **O2 事实体检** | `mem_health` R0 可用，但只被模型按需调用 | 接入巡检日报 + 冲突告警分级 | **高**（记忆不乱的核心检查项） | **S** | **二期 v1 第二片** |

## 三、二期 v1 范围（4 片）

> **进度（2026-11-24）**：BT ✅、BU ✅、CC ✅、CD ✅（v1 完成）；v2 已做 CE（M10 供应链门禁）。

顺序即依赖顺序：先让「事实可校验」，再让「记忆可体检」，然后「成本可刹车」，最后「建议可落地」。

### Slice BT — N2 文档漂移门禁

**目标**：文档里写的路径、环境变量、命令、套件数、能力状态，与代码不一致时 CI 直接红。

**做法**
1. 新增 `docs/status.json` 作为能力状态真源：`{ id, state: done|partial|planned, phase, evidence: [文件路径], note }`。
2. 新增 `scripts/verify-docs.mjs`：
   - Markdown 相对链接目标存在；
   - 文档中的 `DSH_WFXM_*` 环境变量在代码/启动配置中有定义（未落地的变量进脚本内显式 allowlist，落地后必须移出）；
   - 文档中的 `node scripts/<name>.mjs` 与 `pnpm <script>` 存在；
   - 文档引用的 `plugins|scripts|docs|config|deploy|bench` 文件路径存在（通配符/占位符跳过）；
   - `09 §9.3` 的「未做」清单与 `status.json` 一致：`done` 不得出现，`partial/planned` 必须出现，清单里不得有未登记的能力；
   - `README` / `00` 中的「N 套件」等于 `verify-all` 注册数（历史文档的旧数字不校验）。
3. 注册进 [verify-all.mjs](../scripts/verify-all.mjs#L25-L79) 与 CI（[ci.yml](../.github/workflows/ci.yml#L26-L33)）。

> 历史分析文档（`01`/`03`/`04`）引用的是其他仓库路径，只校验链接、不校验行内路径与 `pnpm` 命令。

**非目标**：不校验易变数字（生产版本号、行数、用例数）；不做文档自动生成。

**验收**
- 用本次校正的 3 个漂移（A8/O2/N8）做种子：修正前失败、修正后通过。
- 故意改坏一条路径/一个状态 → 退出码非零并指出文件与行。
- `verify-all` 全绿，套件数同步更新到 00/09。

### Slice BU — O2 事实体检进入巡检

**目标**：事实冲突、过期、孤儿、无来源、失效与复核候选，进入每日巡检日报，而不是等人想起来去问模型。

**做法**
1. `patrol` 增加可选 `memoryHealth` 回调（由 host 注入 `@dsh-wfxm/knowledge` 的 `mem_health` 报告），svcops 不横向依赖 knowledge。
2. 日报追加「事实体检」段：仅在任一计数非零时输出；`probeUnavailable` 只计数、不算失效。
3. 告警分级保守：仅 `conflicts > 0` 触发即时告警，其余进日报；**不自动取代、不自动归档**（保持 A2）。

**非目标**：不做记忆写入策略（G5）；不改 `mem_health` 的五类判据。

**验收**
- 无记忆库 / 无法读取时段落省略，不影响巡检主流程。
- 构造冲突事实 → 日报出现一行、即时告警一次，事实表零改动。
- `verify-patrol` / `verify-knowledge` 新增用例；真机日报可见。

### Slice CC — M8 预算硬限制

**目标**：token 花超了就停，而不是只在日报里看见。

**做法**
1. 配置：`DSH_WFXM_TASK_TOKEN_BUDGET`（单任务）与 `DSH_WFXM_DAILY_TOKEN_BUDGET`（当日累计），为空表示不限制；金额上限复用现有单价配置。
2. 执行中按 `status/step_end` 的 usage 增量累计；超过任务上限 → 终止子进程，任务 `failed(budget-exceeded)`，回执写明已用/上限。
3. 派发前检查当日累计；超限按 owner 决策执行「排队到次日」或「直接拒绝」（见 §六 D2）。
4. 日报增加一行预算使用；不影响既有去重键。

**非目标**：不做按项目/按模型的多级配额；不做费用预测。

**验收**
- 假 usage 流用例：跨线即停，不再产生下一步；未配置时行为与今天完全一致。
- 真机小预算任务被硬停，任务终态与回执正确。
- 当日上限触发时新任务按 D2 语义处理。

### Slice CD — G4 建议 v1

**目标**：日报末尾给出 1–3 条「现在该做什么」，有依据、可拒绝、不自动执行。

**输入**（全部只读）
- 未决巡检候选（`inspection_candidates`）；
- 近 7 天任务失败归类（重试耗尽 / 判据失败 / 冲突）；
- 事实体检的复核候选；
- 当日预算使用率（来自 M8）。

**做法**
1. 生成规则优先、模型兜底：规则能命中就不调用模型；输出结构与去重键固定。
   v1 先落规则（`plugins/svcops/src/suggestions.ts`），模型兜底留到有真实需求再加。
2. 每条建议 = 一句话行动 + 依据（任务/候选/事实 id）+ 风险级别；总量 ≤3。
3. 只进日报，不建任务；owner 回复「做 #1」走正常 R2/R3 流程（执行仍受审批与判据约束）。

**非目标**：不做「一键执行」；不做跨天建议追踪（v2 再说）。

**验收**
- 四项输入全空时不出段；建议数 ≤3；重复日报不重复建议（沿用 outbox 幂等键）。
- 建议不会绕过审批创建任务（用例断言 tasks 表零新增）。
- 真机运行一周，统计采纳率。

### Slice CE — M10 供应链门禁（v2）

**目标**：依赖来源、版本区间、锁文件来源与许可证在 CI 可校验；不靠人记。

**做法**
1. 新增 [scripts/verify-supply.mjs](../scripts/verify-supply.mjs)：内部依赖必须 `workspace:` 且目标包存在；外部依赖禁用 `file:`/`link:`/`git`/`http`/`npm:` 别名与 `*`/`latest`；每个外部依赖必须在 `pnpm-lock.yaml` 有记录；已安装的直接依赖许可证必须在白名单（MIT/ISC/Apache-2.0/BSD/0BSD/BlueOak/CC0/Unlicense）。
2. 声明了依赖但锁文件缺 importer 的包直接失败；**既有** 4 个漂移（`calendar`/`changes`/`mail`/`reminder`）列入显式基线并逐日报告警，锁文件重生成后必须删除基线项。
3. 注册进 `verify-all`（第 2 套件）与 CI；不改运行时、不发布。

**非目标**：不做传递依赖 SBOM；不做自动升级/漏洞库比对；不在此仓库执行 `pnpm install`。

**验收**
- 脚本自带 7 个反例（协议/浮动区间/内部目标缺失/锁文件缺记录/GPL/未登记 importer/基线）；
- 真实仓库扫描 `findings=0`，4 条基线告警；
- `verify-docs` 套件数同步为 51。

## 五、依赖与顺序

```
BT 文档门禁 ──▶ BU 事实体检入巡检 ──▶ CD 建议 v1
                      │
CC 预算硬限 ──────────┘（预算使用率作为建议输入，不硬依赖）
```

- BT 先做：它保证后面三片的文档与状态不再漂。
- BU 与 CC 可并行（前者只读巡检，后者执行链）。
- CD 依赖 BU 的体检输出与 CC 的预算行；BT 保证 CD 的状态口径可校验。

## 七、度量与结项口径

| 维度 | 指标 | 目标 |
|---|---|---|
| 文档 | 漂移门禁在 CI 中的拦截次数 | >0 且修复后归零 |
| 记忆 | 每周期体检报告数 / 冲突处置率 | 冲突 100% 进日报 |
| 成本 | 超限任务数、日均 token、日均费用 | 无静默超限 |
| 建议 | 日报建议条数、采纳率 | 每周 ≥1 条被采纳 |
| 供应链 | 非 registry 协议 / 浮动区间 / 非白名单许可证 | 0（CI 拦截） |

**结项判据**（与一期一致）：代码 + 真机为准，不以计划为准；`verify-all` 全绿（含新增套件）；生产发布走 prepare → verify → switch 流程。
