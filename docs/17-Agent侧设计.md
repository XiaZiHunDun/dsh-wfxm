## 一、范围与四条原则

**Agent 侧 = 五件事**：系统提示装什么、工具暴露哪些、skill 怎么写、子代理怎么拆、判级与验证怎么落地。

| # | 原则 | 依据 |
|---|---|---|
| 1 | **全部挂在宿主既有扩展点上**：`system-prompt/assemble`、工具注册、`tools/pre-execute`、`agent/pre-step`、`subagent`、`skill` | AR29（只干预不替换）、11 §三 |
| 2 | **规则先于模型**：能枚举的判断写成规则，模型只做规则覆盖不到的判断 | 11 §三·决策层（S1 先手） |
| 3 | **判据先行**：没有可执行判据的任务不许 R2+ | 13 §3.1、08 O3 |
| 4 | **工具是手脚、skill 是说明书、preset 是能力声明**，三者不混用 | 本节 §四/§五/§二 |

**明确不做**：不做提示词调优工程（结构对了再谈措辞）；不接第二套 agent 框架；不让子代理或专家持有治理权（AR34）。

## 二、会话类型与 preset

宿主用 preset 决定"这个会话有哪些工具、哪些提示、哪些 skill"。**我们用 5 个 preset 覆盖全部会话**，不外延。

| preset | 谁在用 | 工具面 | 默认预算 | 能否发审批 | 备注 |
|---|---|---|---|---|---|
| `chat` | owner 直接对话 | 全部 A 域 + 检索 + 任务 + 记忆 + 生活 | 30 步 / 30 分钟 | 能（R2/R3 经内核） | 默认会话，绑定 `project_id` |
| `task` | 任务 worker 驱动 | 同 `chat`，去掉"对话专属"工具 | 按任务对象 | 能 | 由 `delegate_task` 创建，无对话面 |
| `dispatcher` | 唯一调度会话（AR25） | **只保留 `task_*` 三个工具** | 5 步 | **不能** | 只建任务不执行业务 |
| `subagent-ro` | 只读子代理（检索、调研、审阅） | A 域只读 + 检索 | 15 步 | **不能** | 结果只回结论 + locator |
| `expert` | 专家执行器（编码/浏览器等） | A 域读写 + 跑测试 | 按任务对象 | **不能**（AR34） | 无自有凭据、事件回传 |

**三条硬约束**

1. **preset 是权限上限，不是权限来源**：实际权限 = `preset 工具面 ∩ parent_grant ∩ task_scope`（AR30）。preset 里写了也不等于能用。
2. **会话类型不可就地升级**：`subagent-ro` 不能靠对话把工具"要"过来；要提权只能新开带 Grant 的会话。
3. **`dispatcher` 只有一个**：启动自检拒绝多 dispatcher（AR25）。

## 三、系统提示结构

### 3.1 六块结构（顺序固定）

顺序即优先级：**越靠前越稳定、越不可裁**；靠后的是动态内容，便于 prompt 缓存。

| # | 块 | 内容 | 来源 | 预算 | 可裁 |
|---|---|---|---|---|---|
| 1 | **身份与边界** | 我是谁、服务谁、四域是什么、什么永不执行（资金类、绕过审批） | 常量（bundle 内置） | 8% | ❌ |
| 2 | **治理硬约束** | R0–R3 默认行为、确认粒度是计划、不可信内容只当数据、无审计即未完成 | 常量 | 12% | ❌ |
| 3 | **交付与输出规范** | 大输出落文件给 locator、结论先给、失败要带证据、附件与长度上限 | 常量 | 6% | ✅ |
| 4 | **项目上下文** | 项目名、根目录、构建/测试命令、约定、默认专家、当前分支 | `projects` 表 + 项目内约定文件 | 14% | ✅ |
| 5 | **记忆与事实** | 检索到的事实卡（**带来源与时效**）+ 已确认偏好 | MemoryPort.search | 20% | ✅ 先裁 |
| 6 | **任务与计划** | 当前目标、计划 DAG、进度、成功判据、剩余预算 | TaskRuntime 任务对象 | 40% | ❌ |

> 与 [13 §2.1](13-核心能力方案.md) 的四块预算（20/30/35/15）是**同一件事的两种切面**：
> 13 管"上下文装什么"，本节管"提示里怎么排"。两处合计约束：
> **固定块（1–3）≤ 26%，任务块 ≥ 40%，检索块 ≤ 20%，其余给近期对话。**

### 3.2 注入规则

| 规则 | 要求 |
|---|---|
| **只写我们的工具名** | 提示与 skill 里出现的工具名必须是登记名，不得出现插件/包/产品名（AR4） |
| **不可信内容不进指令层** | 网页、邮件、日志原文只进"数据区"，不进"规则区"；提示里显式声明这条分区 |
| **项目上下文来自注册表** | 不允许在提示里硬编码路径；路径一律来自 `projects` 表 |
| **无记忆时显式说明** | MemoryPort 不可用 → 注入"本次无长期记忆"，**不静默当作没有事实**（AR13） |
| **预算超限被裁要留痕** | 裁掉哪些块写 `decisions.reason`，便于解释"它为什么忘了" |

### 3.3 对话与任务的差异

- `chat`：块 6 装"当前对话目标 + 待办"，不装完整计划。
- `task`：块 6 装完整计划 DAG、**成功判据**、已用步数/预算；对话历史只保留摘要（任务块不可裁）。

## 四、工具集清单（暴露面）

**命名规范**：`域_动作`（snake_case），一工具一动作；名字只描述能力，不描述实现（AR4 / AR32）。
每个工具在注册时必须同时登记三件事：**schema（由类型生成）**、**风险基线（R0–R3）**、**所属端口**。
三件缺一，启动自检拒绝注册。

### 4.1 工具清单

| 组 | 工具 | 能力 | 端口 | 风险基线 | 可见 preset |
|---|---|---|---|---|---|
| **文件** | `fs_read` | C1 | Exec | R0 | 全部 |
| | `fs_write` / `fs_edit` | C1/C2 | Exec | R1 | `chat` `task` `expert` |
| | `fs_glob` / `fs_search` | B1 | Exec | R0 | 全部 |

| **检索** | `web_search` / `web_fetch` | J6 | Search | R0 | `chat` `task` `subagent-ro` |

| **记忆** | `memory_search` | F5 | Memory | R0 | 全部 |

| **主机** | `svc_list` / `svc_status` / `svc_logs` | C6 | SvcOps | R0 | `chat` `task` |

> **`task_control` 的"取消"是 R2**：中断别人的工作可逆但影响他人在跑的进度；不做 R3，因为它随时可重跑。

### 4.2 粒度六条规则

1. **专用端口优先**：起停服务只走 `svc_*`，**不允许**用 `exec_run("systemctl ...")`。理由：`SvcOps` 的判定粒度是 unit，命令行判定会漏（11 §三）。
2. **`exec_run` 收参数数组，不收 shell 字符串**（15 的 `ExecPort` 签名）；需要管道时由模型显式组合，内核不做字符串解析。
3. **域 B 不给自由 shell**：域 B 只有 `svc_*` + 注册过的 `unit/容器`名单，命令白名单在闸里判。
4. **任务类只暴露三个**：`task_submit` / `task_status` / `task_control`；内部状态迁移（`waiting_approval` 等）不可由模型直接写。
5. **记忆写入必带来源**：`memory_write` 的 schema 强制 `source` 字段，缺来源在参数校验阶段即拒绝（13 §2.3 纪律 3）。
6. **工具可换，闸不可绕**：任何替换实现必须声明 `replaces` 并接入同一 `tools/pre-execute` 链（AR31）。

### 4.3 不暴露清单（管理面，不是工具）

以下能力**只走 Web 渠道的管理页**，不进模型工具面（AR26）：

| 能力 | 为什么 |
|---|---|
| 写 Grant / 撤 Grant | 授权不能被模型自我扩权 |
| 改配置、装/卸插件 | 域 D，最高危 |
| 审计检索与导出 | 只读但含全量历史，不注入上下文 |
| 项目注册与注销 | 影响全局检索边界 |
| 全局中止 | 人类开关，模型不该有 |
| 浏览器 profile 管理（登录态） | 凭据相邻，单独入口 |

## 五、skill 划分

**skill 是按需加载的操作手册**，与 preset、提示块的区别：

| 形态 | 生命周期 | 装什么 | 谁决定加载 |
|---|---|---|---|
| **preset** | 常驻 | 工具体、提示块、预算 | 会话创建时 |
| **提示块** | 每轮重装 | 规则、项目上下文 | 装配器 |
| **skill** | **按需** | 固定步骤、易错点、输出模板、命令清单 | 模型（`skill` 工具）或 owner（`/名称`） |

用宿主 `skill` 家族现成能力：`skill`（注册表）+ `skill-filesystem`（从项目/自定义/用户目录发现）+ `tool-skill`（目录与加载工具）。

### 5.1 目录与来源

```
<项目根>/.dsh-wfxm/skills/<name>/SKILL.md    项目级（随项目库，可版本控制）
/var/lib/dsh-wfxm/skills/<name>/SKILL.md     用户级（owner 私人流程）
bundle 内置 skills/                          内置（随版本发布）
```

优先级：**项目级 > 用户级 > 内置**（同名覆盖，覆盖关系写审计）。`SKILL.md` 只含 Markdown + 可选 `scripts/`、`references/`。

### 5.2 什么时候该写成 skill（判定四条）

1. 步骤固定且会复用（发版、接入新项目）；
2. 有**易错点**需要显式提醒（飞书权限改完要发布版本）；
3. 输出格式固定（周报、变更单）；
4. 领域知识密集但不必每轮进提示（排障树、日志模式）。

四条都不满足 → 写进项目约定或提示块，不要造 skill。

### 5.3 MVP 六个 skill

| skill | 解决 | 关键内容 |
|---|---|---|
| `project-onboarding` | 新项目接入 | 识别类型 → 注册 `projects` → 写构建/测试命令 → 声明默认专家 |
| `release` | 发版 | 前置快照 → 构建 → 迁移检查 → 蓝绿切换 → 验证 → 回滚点 |
| `service-triage` | 服务排障 | `svc_status` → `svc_logs` → 端口/资源 → 只报告不擅修 |
| `log-forensics` | 日志定位 | 时间窗 → 关键字 → 关联 `correlation_id` → 落附件 |
| `change-rollback` | 变更回滚 | 找 `changes` 记录 → 定位 `snapshots` → 演练还原 |
| `mail-triage` | 邮件处理 | 搜索 → 摘要 → 草稿 → **发送前回显收件人/主题/正文** |

### 5.4 skill 的治理

- **skill 里的脚本走同一闸**：`scripts/` 里的命令仍过 `tools/pre-execute`，skill 不能"声明豁免"。
- **skill 不得自带审批**：需要确认的动作回到内核审批（AR34 同理）。
- **skill 引用工具用登记名**（AR4）；换实现不改 skill。
- **skill 变更写审计**：新增/覆盖/删除都要留痕，否则无法解释"它为什么这么做"。

## 六、子代理拆分策略

### 6.1 什么时候拆（三判据，满足其一才拆）

| 判据 | 例子 | 反例（不该拆） |
|---|---|---|
| **上下文隔离** | 读 20 个文件做调研，结论只需 1 段 | 同一文件的连续编辑（会产生冲突） |
| **并行加速** | 同时跑多个项目的只读检查 | 有先后依赖的步骤 |
| **权限收窄** | 只读审阅不该有写权限 | 需要全局判断（阶段收尾、验收） |

### 6.2 形态与上限

| 形态 | 宿主能力 | 用途 |
|---|---|---|
| 进程内 fresh | `subagent-spawn-in-process` | 只读调研（`subagent-ro`） |
| 进程内 fork | `subagent-fork-in-process` | 需要父级已完成的上下文 |
| 进程外 | `subagent-acp` / `subagent-codex` / `subagent-claude-code` / `subagent-dsh-sdk` | 专家执行器（`expert` preset，AR34） |

**上限**：深度默认 **1**（最大 2）；单任务并发 **3**；每个子代理独立 `timeout` 与 `budget`，超限即终止。

### 6.3 权限与回收（AR30 的具体化）

| 项 | 要求 |
|---|---|
| 权限 | `effective = parent_grant ∩ task_scope ∩ preset 工具面`；越域子任务需显式授权 |
| 撤销 | 父 Grant 撤销 → 子代理**立即失效**（下一轮 pre-execute 被拒） |
| 审计 | 子代理每次工具调用都进同一 `audit_log`，带 `parent_task_id` |
| 结果 | 只回**结论 + 证据 locator**，不回全量对话；完整轨迹留在子会话日志 |
| 禁忌 | 子代理不得 `task_submit`、不得审批、不得写记忆正本、不得出 A 域 |

> ⚠️ 宿主 subagent 默认与父**共享** admission/ownership，与 AR30 方向相反。
> **启用前必须验**：父无域 B 授权时，子代理调 `svc_stop` 必须被拒。

## 七、S1 规则集（判级里可确定的部分）

### 7.1 规则形态

- **输入是结构化信号，不是原始命令字符串**：`tool`、`params`（已过 schema）、`domain`、规范化 `path`、`unit`、`network_tier`、`grant`、`risk_baseline`。
- **有序、首命中**：规则有稳定优先级；命中即产出 `allow / ask / block + reason_code`，不再往下判。
- **只上调不下调**：规则可把 R1 提到 R3，**不可**把 R3 降成 R1（AR11 双闸取严）。
- **未命中 → 保守默认**：域 A 读写按 `risk_baseline` 放行；**其余一律 ask**。
- 每次命中写 `decisions`：`rule_id + choice + reason + confidence=1.0`（规则命中的置信度是确定的）。

### 7.2 规则表（30 条，v1）

**A 路径与域（8）**

| # | 规则 | 结果 |
|---|---|---|
| A1 | 写类工具且规范化路径在 workspace 外 | `ask`（自动升 R3，见 AR11 越域即升级） |
| A2 | 路径含 `credential` / `data` / `state` 目录 | `block`（内核自身除外） |
| A3 | 路径解析后经 symlink 逃出 workspace | `block` |
| A4 | 读类工具且路径在 workspace 内 | `allow`（R0） |
| A5 | 会话带 `project_id` 但项目未注册 / 已注销 | `ask` |
| A6 | 直写 `.git/`（非 git 工具） | `block` |
| A7 | 读类工具且路径在 workspace 外 | `ask` |
| A8 | 同 workspace 已有运行中的写任务（租约冲突） | `block`（AR8） |

**B 命令与执行（7）**

| # | 规则 | 结果 |
|---|---|---|
| B1 | `argv[0]` ∈ {`systemctl`,`service`,`docker`} | `block`（走 `svc_*`，见 4.2 规则 1） |
| B2 | `argv[0]` ∈ {`mkfs`,`dd`,`shutdown`,`reboot`} | `block` |
| B3 | `rm` 且目标在 workspace 外 | `ask`（R3） |
| B4 | 含 `sudo` / `su` / `doas` | `block` |
| B5 | 参数含凭据形态（密钥、token、长随机串） | `block` + 脱敏提示 |
| B6 | 预计时长 > 5 分钟 | `allow` 但强制后台（`exec_start`） |
| B7 | 命令落在域 B 且不在白名单 | `block` |

**C 网络与出站（5）**

| # | 规则 | 结果 |
|---|---|---|
| C1 | 目标域名不在 allowlist 且网络档为 `off` | `block` |
| C2 | allowlist 内未见过的域名（首用） | `ask`（一次批准后入 allowlist） |
| C3 | 上传本地文件到外部 | `ask`（R3） |
| C4 | 目标为 `localhost` / 内网段（防 SSRF） | `block` |
| C5 | 目标域名在 allowlist 且为读操作 | `allow` |

**D 主机与服务（6）**

| # | 规则 | 结果 |
|---|---|---|
| D1 | 目标 unit / 容器不在注册表 | `block` |
| D2 | `svc_start` / `svc_restart` 且 unit 已注册 | `ask`（R3） |
| D3 | `svc_stop` 且 unit 是 `dsh-wfxm` 自身 | `block`（升级走自有脚本） |
| D4 | 删除非 workspace 文件 | `ask`（R3） |
| D5 | 目标 unit 存在但适配器未探活 | `block` + `NotSupported`（不静默换路，AR13） |
| D6 | `svc_*` 且当前有未完成变更（`changes` 未闭合） | `ask`（回滚窗口内不允许第二个变更，11 §八） |

**E 生活域与外发（4）**

| # | 规则 | 结果 |
|---|---|---|
| E1 | `mail_send`：任何目标 | `ask`（R3，回显收件人/主题/正文） |
| E2 | 外发正文含凭据形态 | `block` |
| E3 | `cal_create` 含外部参会人 | `ask` |
| E4 | 浏览器落在支付/下单/转账页面 | `block`（08 J 域名硬规则：资金类永不执行） |

### 7.3 什么时候 S1 不够，升级 S2

只有四种情况交给模型判断，**其余不许多花一次推理**：

1. 意图歧义（一句话可能指两件事）；
2. 规则的**输入信号缺失**（如路径尚未确定、目标 unit 由别处推导）；
3. 规则给出 `ask` 但 owner 已给了计划级授权——由 S2 判断"这次是否落在授权范围内"；
4. 两个规则冲突且无法静态排序。

**S2 的输出仍要写成结构化结果**（`choice + confidence + reason`），且**只能收紧、不能放宽 S1 的 block**。

### 7.4 规则集的变更纪律

- 规则是**产品决策**，不是实现细节：新增/删除规则要改本节 + 写审计，规则集带 `ruleset_version`。
- **每条规则至少一个单测用例**（构造输入 → 期望 `choice`），并在契约测试里跑。
- **命中率与误判率进指标**（11 §八 可观测的"决策"类 + 本文 §8.8）：长期 `ask` 过多的规则要合并或降级。

## 八、Verifier：断言从哪来、怎么安全执行

### 8.1 断言 DSL（7 种，与 15 的 `task_assertions` 一致）

| kind | 参数 | 由哪个端口执行 |
|---|---|---|
| `exit_code` | `expected` | Exec |
| `file_exists` | `path`、可选 `sha256` | Exec |
| `port_listening` | `port`、可选 `host` | Exec（只读探测） |
| `service_active` | `unit` | SvcOps |
| `http_status` | `url`、`expected` | Search（只读） |
| `git_diff_matches` | `ref`、`paths`、`expect` | Exec |
| `page_contains` | `url`、`selector`、`expect` | Browser |

> **新增 kind 必须同时改本文与 15 的 `CHECK` 约束**，否则迁移与代码会各说各话。

### 8.2 断言的三个来源（按优先级）

| 级 | 来源 | 适用 | 校验强度 |
|---|---|---|---|
| **① owner 显式** | 对话里说"成功就算 X" → 转成结构化断言 | 一次性任务 | 转写后回显给 owner 确认 |
| **② 模板库**（首选） | 按任务类型映射标准断言组（见 8.3） | 发版、服务操作、邮件发送、构建 | 模板本身经评审，不逐次校验 |
| **③ 模型生成**（受约束） | 模型只从 DSL 里**选**，不能写自由文本 | 模板未覆盖的任务 | schema + 静态校验（8.4） |

**模型生成的边界**：模型输出的是 `AssertionSpec[]`（JSON），由内核校验后才落 `task_assertions`。
**模型不能定义"什么算成功"的新类型**，只能组合已注册的 kind。

### 8.3 模板库（v1 五组）

| 任务类型 | 标准断言组 |
|---|---|
| 构建/测试 | `exit_code(0)` + `file_exists(产物路径)` |
| 发版 | `exit_code(0)` + `service_active(unit)` + `port_listening(端口)` + `http_status(健康检查, 200)` |
| 配置变更 | `exit_code(0)` + `file_exists(配置)` + `service_active(unit)` |
| 代码修复 | `exit_code(0)`（测试）+ `git_diff_matches(提交, 预期文件)` |
| 邮件发送 | `exit_code(0)` + 发送记录 `evidence`（不接受"模型自称已发"） |

### 8.4 生成断言的静态校验（五条，任一失败即拒绝）

1. `kind` 在白名单内；
2. `target`（unit / 端口 / 路径 / URL）**已在注册表或配置中登记**；
3. `path` 规范化后在域 A 或域 B 允许范围内；
4. 参数里**不得出现 shell 片段 / 通配符扩张**；
5. 单任务断言数 **≤ 8**（防"断言刷量"掩盖真实失败）。

### 8.5 安全执行六条

| # | 要求 | 理由 |
|---|---|---|
| 1 | **只经端口执行**：Exec / SvcOps / Search / Browser，不新开执行通道 | 闸只有一条（AR31） |
| 2 | **断言必须只读**（R0）：不得产生副作用 | 否则"用验证改坏了系统" |
| 3 | 独立 `timeout`（默认 60s）+ 独立预算 | 防止验证拖死任务 |
| 4 | 不读凭据、不把响应正文进上下文（只留摘要 + locator） | 防泄漏 |
| 5 | 结果落 `task_assertions`（`status` / `evidence_json` / `checked_at`）+ 审计事件 | AR15 |
| 6 | **断言失败不自动重试断言本身**：先判断"是结果错还是判据错" | 判据可疑时重试只会放大误判 |

### 8.6 失败处置三分支

| 现象 | 处置 |
|---|---|
| `Transient`（超时、探测抖动） | 断言重测一次（**只测一次**），仍失败转下一条 |
| 结果确实不符、动作可重试 | 走任务重试分级（13 §3.3），**必须带幂等键** |
| 已发生不可逆影响 | **回滚**（`snapshots`）+ 升级给人，不自动"再修一次" |

### 8.7 无判据的任务

- 只能 **R0–R1**（只读 / 工作区内可逆），不允许 R2+（13 §3.1）。
- `task_submit` 时若 `risk_level ≥ R2` 且无断言 → **直接拒绝提交**并说明原因。

### 8.8 度量

| 指标 | 目标 |
|---|---|
| R2+ 任务带断言比例 | **100%** |
| 断言假阳性（通过但实际坏）抽查 | 每两周抽 10 条 |
| 模板复用率 | 逐季上升；低于 50% 说明模板库设计有问题 |

## 十、验收（8 条，全部要真实跑通）

| # | 验收点 | 判据 |
|---|---|---|
| 1 | **零干预基线**（AR29） | 关闭全部编排策略后，基础对话与任务仍跑通 |
| 2 | **提示不绑实现**（AR4） | 提示与 skill 全文搜不到插件/包/产品名（CI lint） |
| 3 | **未登记工具被拒**（AR31） | 临时注入一个跳过 `pre-execute` 的工具，调用必须失败 |
| 4 | **子代理不放大**（AR30） | 父无域 B 授权时子代理调 `svc_stop` 被拒；撤销父 Grant 后立即失效 |
| 5 | **无判据不许 R2+** | 提交无断言的 R2 任务被拒绝，且给出原因 |
| 6 | **断言只读** | 跑完全部断言后 `git status` 与系统状态无变化 |
| 7 | **规则集可测** | 30 条规则各有 allow/ask/block 用例，全部通过 |
| 8 | **非法断言被拒** | 构造越域路径 / 未注册 unit / 含 shell 片段的断言，全部在静态校验被拒 |
