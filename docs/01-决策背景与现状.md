# 01 — 决策背景与现状

## 为什么迁（owner 一手判断）

这是决策的**主要依据**，来自 owner 实际使用 WFXM 的观察，不是文档对比得出的：

1. **对话质量会退化** —— "聊着聊着就乱掉了"。
   一个已定位的具体成因：CI smoke 日志里反复出现
   `[conversation-loop] decodeDecision failed at iteration N: invalid JSON`。
   但ler 的 agent loop 在模型输出不合约时**静默降级**（落到 plain-text → Respond），
   而不是像 dsh 那样直接抛错（`history ends with unresolved tools` → `INVALID_REQUEST`）。
   这类问题在 dsh 侧是结构性不存在的。
2. **功能简陋** —— 多项能力未经人工测试验证，只在 fixture 层跑过。
3. **dsh 是经过大量验证的开源产品** —— 1644 个 `.spec.ts`、20 万+ star、社区插件生态。

### 设计哲学：一切皆插件

`docs/architecture.md:9-11` 原文：

> Every part of the product is a plugin, including the model adapter, the tool registry,
> the session log, and the agent loop itself, so each is replaceable from configuration.
> There is no privileged core to patch: you extend dsh by mounting a plugin beside the others,
> and registrations are effects that unwind when their plugin unloads.

服务注册在 `ctx.<key>` 槽位上（如 `ctx.tools`、`ctx.llm`、`ctx.sessions`、`ctx.agents`），
其他插件按 key 发现，**不 import 具体实现**。

### 扩展接缝

**profile + 有序 bundle + patch 文件**（`docs/architecture.md:13-25`）：
profile 列出有序 bundle，bundle 是 Cordis config 行的分发格式，patch 按 row id **整行替换 config**。
这就是"不用改源码"的机制基础。

## 必须知道的三条硬约束

### 1. 没有 in-process 嵌入契约

`docs/architecture.md:45` 原文：

> direct in-process plugin mounting … are not Harness application launchers

且有 gate 脚本 `scripts/verify-application-entrypoints.ts` **主动拒绝**任何绕过 `dsh` 的 Node 启动路径。

官方唯一支持的接入方式：**子进程 + stdio 上的 JSON-RPC**（`@deepseek-ai/dsh-sdk-client`，
`createProcessDeepSeekHarness()`），深度定制靠 profile + patch 文件。
SDK client 与 dsh **必须同版本**（`packages/sdk/client/src/launch.ts:58-60`）。

### 2. 未做安全审计

`SAFETY.md:7` 原文：

> DeepSeek Harness is experimental developer-preview software.
> It has not undergone a security audit and must not be treated as secure or production-ready.

`SAFETY.md:13` 还写明沙箱与审批"do not guarantee isolation"。

**这不代表 dsh 不好**，但意味着：把它接进个人微信账号（一个有真实身份、有通讯录、能发文件的环境）
是一个需要自觉加权的决定。Butler 现有的治理层正是这一层防护。

### 3. 明确承诺破坏性变更

`README.md:13`：

> **THERE WILL BE COMPATIBILITY-BREAKING CHANGES.**

社区插件的历史也印证了这点 —— dsh-im issue #253 是跨版本直接炸 `SessionFormatError` 的先例。
